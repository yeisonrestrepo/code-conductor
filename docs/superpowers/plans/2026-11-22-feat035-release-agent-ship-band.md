# FEAT-035 Release Agent (Ship Band): implementation plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking. Update one checkbox per edit (BUG-003 invariant). Execute in file order.

**Goal:** an eighth band role, `release`, seated in the Ship band and existing only at SNAP `v: 6`, shipped to every installed project with a new zero-dependency driver, `scripts/release.mjs`, that hardcodes no project fact. Every fact about how a project releases lives in its committed release profile, `.claude/release-profile.json`. `/cc-release --init` proposes the profile from the project's files and writes it only on the owner's confirmation; `/cc-release <version> [--items <IDs>]` runs `digest` (clean tree, green checks, an advancing version), dispatches the `release` agent (`Read, Grep, Glob, Edit`) inside an envelope whose `ops.scope` is the profile's surface, and judges the uncommitted diff with `check` (line by line against `HEAD`, then the profile's checks in order, halting `RELEASE_HALT <name>: exit <rc>` on the first red one); `/cc-release --handoff <version> [--pr <N>]` re-runs the checks at the merged `HEAD` and prints the tag, push, publish and ticket writeback `STEP` lines the command runs one owner confirmation at a time. This repository commits its own profile, whose checks are `tools/version-gate.mjs` then `tools/record-parity.mjs`, unchanged and unshipped.

## Plan decisions the spec leaves to the implementation

1. **The error type and exit codes.** `release.mjs` exports `class ReleaseError extends Error` with `code` and `reason` (message `<code>: <reason>`). A refusal prints `release: <CODE>: <reason>` on stderr and exits 2. A halt and a failed judgment print on stdout and exit 1. Success exits 0. `envelope release` turns a `ReleaseError` into `Halt(e.code, e.reason)`, which `envelopeVerb` prints as `orchestrate: <CODE>: <reason>`, exit 2.
2. **Argument grammar.** `init [--confirm]`; `digest --version <v> [--items <IDs>] [--date <YYYY-MM-DD>]`; `check` the same; `handoff --version <v> [--pr <N|url>]`. Options may come in any order, each at most once; an unknown option, a missing value, a value that starts with `-`, `--items` with an id outside `[A-Za-z0-9._-]+` or a repeated id, a `--date` that is not a real `YYYY-MM-DD` date, and a `--pr` that is neither `^[1-9]\d*$` nor `https://github.com/<owner>/<repo>/pull/<n>` (ticket.mjs's two forms) refuse `RELEASE_USAGE` with `usage: release.mjs init [--confirm] | digest --version <v> [--items <IDs>] [--date <YYYY-MM-DD>] | check --version <v> [--items <IDs>] [--date <YYYY-MM-DD>] | handoff --version <v> [--pr <N|url>]`. The usage check runs first, before any git call.
3. **Root and profile reads.** The CLI root is `git rev-parse --show-toplevel` from the working directory; a failure refuses `RELEASE_NOT_A_REPO: <dir> is not inside a git work tree` (`init` included). `loadProfile(root)` checks `git -C <root> rev-parse --is-inside-work-tree` (else `RELEASE_NOT_A_REPO`), reads `git show HEAD:./.claude/release-profile.json` with `cwd` = root (the `./` form is relative to `root`, which is what `envelope release` passes, see decision 18), refuses `RELEASE_NOT_CONFIGURED: no release profile at HEAD; run /cc-release --init` when that fails (no `HEAD`, or the file is not in it, including written but not committed), refuses `RELEASE_PROFILE_INVALID: profile: not a JSON object` when it does not parse to a plain object, and returns `{ profile: validateProfile(obj), blob }`, `blob` from `git rev-parse HEAD:./.claude/release-profile.json`.
4. **The validator, `validateProfile(obj)` (exported).** Every failure is `RELEASE_PROFILE_INVALID: <field>: <reason>`, `<field>` a path such as `versions[2].line` or `checks`. The checks, in this order:
   - Top-level keys exactly from `versions, changelog, tag, remote, mainline, checks, publish, backlog, ticket`; all but `backlog` and `ticket` required (`publish` may be `null`). Every nested object likewise rejects unknown keys and requires its keys.
   - `versions`: a non-empty array; each entry `{ path, json }` with `json` a non-empty array of strings, or `{ path, line }` with `line` a template; never both. One path holds only `json` entries or one `line` entry.
   - `changelog`: `null` (A2) or `{ path, heading }`. `tag`: a template whose literal text matches `[A-Za-z0-9._/-]*`. `remote`, `mainline`: `^[A-Za-z0-9][A-Za-z0-9._/-]*$`. `checks`: a non-empty array of `{ name, argv }`, `name` matching `[A-Za-z0-9._-]+` and unique, `argv` a non-empty array of non-empty strings with no placeholder. `publish`: `null` or `{ target, argv }`, `target` a non-empty single-line string with no placeholder. `backlog`: `{ path, open, closed, done, claim }`, with a `null` changelog too (A2, C3: a binding needs `backlog`, not a changelog; `claim` is then unused, because there is no entry to claim from). `ticket`: exactly `{ "writeback": true }`, and only with `backlog`.
   - **Templates.** A placeholder is `{<lowercase letters>}`. An unknown name refuses `unknown placeholder {<name>}`; a known name outside the field's set refuses `placeholder {<name>} is not allowed here`. Allowed and required sets: `versions[].line` allows `{version}`, requires it once; `changelog.heading` allows `{version}`, `{date}`, requires `{version}` once, `{date}` at most once; `tag` allows and requires `{version}` once; `publish.argv[]` allows `{tag}`, `{version}`, `{notes}`, `{sha}`; `backlog.open` and `backlog.closed` allow and require `{id}` and `{title}` once each; `backlog.done` allows `{version}`, `{date}`, requires `{version}`; `backlog.claim` allows and requires `{id}` once. `{title}` is not allowed elsewhere, so every `{title}` the driver renders comes from a matched `open` line.
   - **Paths (C13)**, for every `path`: a non-empty string; not absolute (no leading `/`, no `^[A-Za-z]:`, no `\`); no `..` substring; no glob character `*?[]{}`; no empty, `.` or `.git` segment; not `.claude/release-profile.json` (`the release profile is never on its own surface`). `changelog.path` (when not `null`) and `backlog.path` differ from every version path and from each other.
   - Then the surface caps (decision 5).
5. **`releaseSurface(profile)` (exported)** returns the distinct version paths in first-seen order, then `changelog.path` when the changelog is not `null` (A2: else the surface is the version paths only), then `backlog.path` when bound. 6. **Templates as text.** `render(template, values)` substitutes each placeholder. `templateRegExp(template, captures)` escapes the literal text and maps `{version}` to `(\d+\.\d+\.\d+)`, `{date}` to `(\d{4}-\d{2}-\d{2})`, `{id}` to `([A-Za-z0-9._-]+)`, `{title}` to `(.+)`, or to the literal value when `captures` fixes it; the expression is anchored at both ends. Otherwise `RELEASE_PROFILE_AMBIGUOUS: <path> <line template | json key path> matches <n> lines at HEAD` or `… holds no MAJOR.MINOR.PATCH version at HEAD`. The **current version** is the first location's value. Locations that disagree are **not** refused by the driver: agreement is the project's own check (here `version-gate`), which E1 requires to be the one that halts. Each location is judged against its own `HEAD` value. Versions compare numerically by MAJOR, MINOR, PATCH; `--version` must match `^(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)$` (else `RELEASE_VERSION_INVALID: <v>: only MAJOR.MINOR.PATCH is supported`, A3) and compare greater than the current version (else `RELEASE_VERSION_NOT_ADVANCED: <v> does not advance <current>`).
8. **Refusal order.** `digest` and `check`: `RELEASE_USAGE`, `RELEASE_NOT_A_REPO`, `RELEASE_NOT_CONFIGURED`, `RELEASE_PROFILE_INVALID`, `RELEASE_SURFACE_TOO_WIDE`, `RELEASE_VERSION_INVALID`, `RELEASE_ITEMS_UNBOUND` (`--items` with no `backlog`: `the profile binds no backlog; release without --items`), `RELEASE_USAGE` (`--items is required: the profile binds a backlog`), `RELEASE_TREE_DIRTY` (digest only), `RELEASE_PROFILE_AMBIGUOUS`, `RELEASE_VERSION_NOT_ADVANCED`, `RELEASE_ITEM_UNKNOWN`, `RELEASE_ITEM_NOT_OPEN`, then the checks (`digest`) or the judgment (`check`). `handoff`: `RELEASE_USAGE`, `RELEASE_NOT_A_REPO`, `RELEASE_NOT_CONFIGURED`, `RELEASE_PROFILE_INVALID`, `RELEASE_SURFACE_TOO_WIDE`, `RELEASE_VERSION_INVALID`, `RELEASE_TREE_DIRTY`, `RELEASE_PROFILE_AMBIGUOUS`, `RELEASE_NOT_RELEASED`, `RELEASE_NOT_ON_MAIN`, `RELEASE_TAG_EXISTS`, `RELEASE_USAGE` (`--pr is required: a writeback step will print`), `RELEASE_EXCERPT_TOO_LARGE`, then the checks, and only then any file write.
9. **Items.** For each `--items` id, in order: the backlog lines at `HEAD` matching `open` with that `{id}` (title captured) and those matching `closed`. One `open` line and no `closed` line is the item; no line of either is `RELEASE_ITEM_UNKNOWN: <ID> has no heading in <path>`; a `closed` line (and no `open` line) is `RELEASE_ITEM_NOT_OPEN: <ID> is already closed at line <n>`; more than one `open` line, or both, is `RELEASE_PROFILE_AMBIGUOUS: <ID> has <n> headings in <path>`.
10. **Dirty** is any entry of `git status --porcelain=v1 -z --untracked-files=all` (a rename entry's second path is consumed): `RELEASE_TREE_DIRTY: <n> modified or untracked paths:` then one path per line. Ignored files are not listed by git.
11. **Checks (C6, A1).** Each check runs as `spawnSync(file, args, { cwd: root, encoding: 'utf8', shell: false, maxBuffer: 64 * 1024 * 1024, windowsHide: true, windowsVerbatimArguments: verbatim })`, with the caller's environment and no timeout (a check's duration is the project's). An `argv[0]` of `node` gives `file = process.execPath`, `args = argv.slice(1)`, `verbatim = false` on every platform. Any other `argv[0]` gives `file = argv[0]` off Windows; on `process.platform === 'win32'` it gives `windowsInvocation(argv, { root, env: process.env, isFile })` (exported, pure, so test 56 pins it on every platform; `isFile(p)` is `existsSync(p) && statSync(p).isFile()`), and a `null` result is the `exit 127` halt with the indented line `cannot find <argv[0]> on PATH with PATHEXT <extensions joined by ;>`. `windowsInvocation`:
    - Environment keys are matched case-insensitively (`Path`, `PATHEXT`, `ComSpec`). The extensions are `PATHEXT` split on `;` (empty entries dropped), else `.COM;.EXE;.BAT;.CMD`.
    - The bases: an `argv[0]` holding `/` or `\` gives one base, `path.win32.resolve(root, argv[0])`; a bare name gives `path.win32.join(<dir>, argv[0])` for each non-empty `PATH` entry in order. The root is never searched for a bare name, so a file committed to the project cannot shadow a program on `PATH`.
    - The candidates of a base: the base alone when it already ends, case-insensitively, in one of the extensions; else the base plus each extension in order. The first candidate `isFile` accepts is the program; none gives `null`.
    - A program not ending in `.cmd` or `.bat` (case-insensitive) gives `{ file: <program>, args: argv.slice(1), verbatim: false }`.
    - A `.cmd` or `.bat` program gives `{ file: <ComSpec> or 'cmd.exe', args: ['/d', '/s', '/c', '"' + line + '"'], verbatim: true }`, where `line` is the escaped program, then each escaped argument, joined by one space. With ``META = /([()\][%!^"`<>&|;, *?])/g``: the program escapes as `program.replace(META, '^$1')`; an argument first doubles the backslashes before each `"` and writes the `"` as `\"` (`replace(/(\\*)"/g, '$1$1\\"')`), doubles a trailing backslash run (`replace(/(\\*)$/, '$1$1')`), is wrapped in `"`, and then escapes as `replace(META, '^$1')`, once more when the program matches `/node_modules[\\/]\.bin[\\/][^\\/]+\.cmd$/i` (such a shim passes `%*` through `cmd.exe` a second time). This is the escaping the widely used `cross-spawn` package applies, written here with no dependency; the profile's arguments stay data, and no profile text is ever a command line. Exit 0 is green. Otherwise the verb prints, on stdout, `release: RELEASE_HALT <name>: exit <rc>`, then each line of the command's stdout, then each line of its stderr, each indented two spaces, and exits 1; no later check runs and the verb prints nothing else. `<rc>` is the exit status, the signal name when the process was killed, or `127` when it could not start, in which case the indented line is the spawn error's message. A green run prints `CHECK <name> ok` per check (digest, check, handoff).
12. **The digest (stdout, exit 0), in order:** `RELEASE <v> FROM <current> DATE <date>`; `PROFILE <blob>`; `SURFACE <path>` per surface entry; per location, `LOCATION <path> line <n> <new line>` or `LOCATION <path> json <key path as compact JSON> <v>`; `CHANGELOG <path> HEADING <rendered heading> AT <n | end>` (`<n>` the 1-based `HEAD` line of the first heading-template match, before which the entry goes), or `CHANGELOG none` when the changelog is `null` (A2); with a backlog, per item, `ITEM <ID> <line> <title>`, `CLOSED <rendered closed>`, `DONE <rendered done prefix>`, and `CLAIM <rendered claim>` when the changelog is not `null`; then `COMMIT <short sha> <subject>` from `git log --no-show-signature --format=%h%x09%s -n 200 <range>` (newest first), `<range>` = `<tag>..HEAD` for the highest-versioned local tag matching the tag template, else `HEAD`; when the range holds more than 200 commits, `COMMITS-TRUNCATED <n>` with the number not listed; then the `CHECK` lines. Subjects and titles are printed verbatim (C12). `--date` defaults to `new Date().toISOString().slice(0, 10)`.
13. **The judgment (`check`).** Changed paths are `git diff --name-only -z --no-renames HEAD` plus `git ls-files --others --exclude-standard -z`. Failures, printed on stdout as `release: <CODE>: <detail>`, one per line, in this order:
    - `RELEASE_PROFILE_CHANGED: .claude/release-profile.json differs from HEAD` when it is a changed path;
    - `RELEASE_OUT_OF_SCOPE: <path> is outside the release surface [<surface joined by ', '>]` per other changed path off the surface, sorted;
    - `RELEASE_LOCATION_SHAPE: <path> <why>` per version path, surface order. A `line` file: the work-tree text equals the `HEAD` text with exactly the location's line replaced by the template rendered at `<v>`. A `json` file: it parses; each listed key holds `<v>`; setting each back to its `HEAD` value gives a value `util.isDeepStrictEqual` to the `HEAD` parse; and `git diff --numstat HEAD -- <path>` reports exactly as many added and removed lines as the path has locations;
    - `RELEASE_CHANGELOG_SHAPE: <why>`, only when the changelog is not `null` (A2: a `null` changelog has no path on the surface, so an edit to a changelog file is `RELEASE_OUT_OF_SCOPE` above): with `H` the `HEAD` lines, `W` the work-tree lines, `a` the 0-based anchor (decision 12) and `k = W.length - H.length`: `k > 0`, `W[0, a)` equals `H[0, a)`, `W[a + k, …)` equals `H[a, …)`, and `W[a]` is the rendered heading. This is position-exact where a diff hunk can slide on blank lines; the block `W[a, a + k)` is the entry;
    - `RELEASE_BACKLOG_SHAPE: <why>`: the work tree equals `HEAD` with each named item's `open` line replaced by `closed` rendered with its id and title and followed by exactly one inserted line starting with the rendered `done` prefix; nothing else differs;
    - `RELEASE_CLAIMS_MISMATCH: the entry claims [<ids>], --items names [<ids>]`: with a backlog and a changelog (A2: with a `null` changelog there is no entry to claim from, so this judgment does not run, while `RELEASE_BACKLOG_SHAPE` still judges the flips and DONE lines), the claims are the entry's lines matching `^\s*[-*]\s+` followed by the claim template (`{id}` captured), compared as sets with `--items`;

Without a backlog the claims are not judged (no claim template exists).
    Any failure exits 1 and runs no check. With none, the checks run (decision 11); green prints the `CHECK` lines and `release: ok <v>` (plus ` items <IDs>`), exit 0. `check` never writes, stages or reverts.

With a `null` changelog (A2), `notes.md` is one `- <subject>` line per `COMMIT` line that `commitLines` (decision 12's range and cap) gives at `HEAD`, newest first, plus `- and <n> earlier commits` when it gives `COMMITS-TRUNCATED <n>`, each line ending `\n`: the digest's subjects, plus the release's own commits that landed after the digest ran. Every printed argument is POSIX shell-quoted: unchanged when it matches `^[A-Za-z0-9._/:=@%+,-]+$`, else wrapped in single quotes with each `'` written `'\''` (an empty argument is `''`). - **Spawning the checks on Windows (A1).** `npm` and most project tools are `.cmd` shims there, which cannot start without `cmd.exe`. Decision 11 resolves them through `PATH` and `PATHEXT` and builds the `cmd.exe /d /s /c` line itself, escaping every argument and passing it verbatim, so no profile text becomes a command line. The escaping is pinned row by row on every platform (test 56), and test 58 starts the real `npm test` on the Windows leg, the only one where `npm` is a `.cmd` shim; a failure there is a real defect, not ENV. A rename of test 58 or of its `describe` moves its skip identity, and the `ci-node20` and `ci-node24` legs go red naming it until T-208's lines follow. `node` still resolves to `process.execPath`, which this repository's profile uses; the other fixture checks are `.mjs` files run through `node`.
- **Test 58 depends on `npm` being on `PATH`.** The Windows leg runs the suite through `npm test`, so it is; npm writes its log under the user's npm cache, outside the fixture.
- **Fixture git on CI legs.** Fixtures pin identity, signing (`commit.gpgsign`, `tag.gpgsign`) and `core.autocrlf=false`, use `git init -b main` (git 2.28+), and scrub `GIT_*` with `cleanGitEnv` (BUG-053). `release.mjs` runs git with the caller's environment, as `orchestrate.mjs` does. Line splitting strips one `\r`, so a CRLF checkout cannot shift a judgment.
- **Commit-count fixture time.** Test 29 writes 202 commits with one `git fast-import` process, not 202 spawns.
- **The parity tests between the leaves and the commit.** Decision 17: two `gitignore-block-parity` tests are red in the work tree from T-112 to the runner's commit, by construction; T-501 names them so the build is not misread as broken.
- **Root versus top level** (decision 18): the same directory in every installed layout; Guard 5 anchors the scope at the envelope's root.
- **A slow router suite.** `orchestrate.test.js` runs about nine minutes; T-303 and T-306 filter it with the measured match set, and only T-501 runs it whole.
- **Hook mirror drift.** Each hook edit is made twice; `templates.test.js` fails on any byte difference, and T-502 runs `cmp`.
- **`.conductor/` not ignored in a project.** `check` would count `.conductor/handback/release.txt` as out of scope there. Every install's `.gitignore` merge adds `.conductor/` (`project-template/gitignore`), and this repository ignores it; a project that removed the line sees `RELEASE_OUT_OF_SCOPE: .conductor/…`, which names the cause.
