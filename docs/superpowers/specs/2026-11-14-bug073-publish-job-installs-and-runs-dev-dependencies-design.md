# BUG-073: Publish job installs and runs dev dependencies in the job holding the npm OIDC credential

**Status:** Approved 2026-11-14 by the owner

**Item:** `[BUG-073]` (intake of issue #160, from the automated security review of the 1.44.0 release candidate, #157). **Date:** 2026-11-14. **Base:** `main` at `54cfb4f` (`VERSION` 1.52.0, tag `v1.52.0`).

## Problem

`.github/workflows/publish.yml` on the base is one job, `publish`, in the `npm-publish` environment with `permissions: id-token: write, contents: read`. In that job it runs `npm ci` and `npx vitest run`, then the version and re-publish checks, then `npm publish --provenance --access public`. Every dev dependency (`vitest` and `@vitest/coverage-v8`, both `^3.0.0`, and their transitive tree) is installed and executed in the job that can mint the npm publishing credential and that packs the published tarball. Any package in that tree that runs code at install or test time can request the OIDC token from the runner, or change the working tree before `npm publish` packs it.

On the base lockfile, `npm audit --package-lock-only` reports 13 advisories in that tree: 2 critical (`tinypool` <= 2.1.1, prototype-pollution gadgets that lead to code execution), 5 high, 5 moderate and 1 low. The package has no runtime dependencies, so installs by users are unaffected. The exposure is the publish job itself.

## Owner Decisions

- **D1. Two jobs.** `publish.yml` becomes a `verify` job and a `publish` job. `verify` has `permissions: contents: read`, no `environment` and no `id-token`. It runs `npm ci`, `npx vitest run`, "Verify package version matches the release tag" and "Guard against re-publishing an existing version", with their scripts unchanged. `publish` has `needs: verify`, `environment: npm-publish` and `permissions: id-token: write, contents: read`.
- **D2. Nothing from the project tree runs in `publish`.** It checks out with `persist-credentials: false` and runs `actions/setup-node` with `registry-url` and no `cache`. Its only commands are `npm install -g npm@^11.5.1 --ignore-scripts` (OIDC trusted publishing needs npm >= 11.5.1) and `npm publish --provenance --access public --ignore-scripts`. The package has no build step and no pack or publish lifecycle script, so `--ignore-scripts` skips nothing it needs.
- **D3. Deny by default.** The workflow declares a top-level `permissions: {}`, the pattern `wiki-sync.yml` uses, so each job holds only what it declares.
- **D4. Same commit.** Neither job overrides the checkout `ref`, so both build the release's `GITHUB_SHA`, and `publish` packs the commit `verify` tested.
- **D5. Vitest 4, not 5.** `vitest` and `@vitest/coverage-v8` move together to `^4.1.12`, and the lockfile is updated in place with npm 11. npm 10 fails on that update with "Cannot read properties of null (reading 'edgesOut')". vitest 4.1.12 no longer depends on `tinypool` and pins `@vitest/mocker` 4.1.12, past the 4.1.11 advisory bound. Its engines (`^20.0.0 || ^22.0.0 || >=24.0.0`) keep the Node 20 floor (`engines.node` `>=20`, test.yml's `ci-node20` leg). vitest 5.x needs `^22.12.0 || ^24.0.0 || >=26.0.0` and would drop that floor. `vitest.config.js` and `tools/skip-baseline.json` stay unchanged.
- **D6. No audit gate in the workflow.** No workflow gets an `npm audit` step, so a dev-dependency advisory never blocks a publish.
- **D7. Owner-applied workflow commit.** The lane App has no Workflows permission, so the `publish.yml` change is the owner's commit `371647f` on this branch. The rest of the item follows it on the same branch and PR (#234).
- **Kept.** The trigger `release: types: [published]`, the `npm-publish` environment with its tag-only deployment rule (a repository setting, not in the tree), `runs-on: ubuntu-latest`, Node 24 in both jobs, and OIDC trusted publishing with no stored token.
- **Separate items.** Actions stay pinned by tag (BUG-070). `CONTROL_PLANE` is not extended to `.github/workflows/**` or `package.json` scripts (BUG-081). Nested `CLAUDE.md` is untouched (BUG-082). No hook, `scripts/` or other workflow file changes.
- **Records.** `VERSION`, the package version, `CHANGELOG.md`, the backlog checkbox, the README Known-limits line for `[BUG-073]` and `.claude/memory/**` are written at release (1.52.1), not by this item.

## Solution

1. **Workflow** (owner commit `371647f`). D1 to D4, as above. The `BUG-048` comment on why `verify` has no skip-baseline step and the npm 11 pin comment move with their steps.
2. **Dev toolchain.** `package.json` `devDependencies` become `"@vitest/coverage-v8": "^4.1.12"` and `"vitest": "^4.1.12"`. `package-lock.json` is regenerated by `npx npm@11 install --save-dev --package-lock-only --ignore-scripts vitest@^4.1.12 @vitest/coverage-v8@^4.1.12` from the base lockfile. It resolves `vitest`, `@vitest/coverage-v8` and `@vitest/mocker` at 4.1.12 and `vite` at 8.3.8, has no `tinypool`, and keeps the native optional bindings for every platform the CI matrix runs.
3. **Tests.** `tests/installer/workflow.test.js` is rewritten to assert per job. It reads the workflow without comment lines and slices it at the `jobs:` keys, with no YAML dependency. It also pins the toolchain rows below.

## Acceptance Criteria

- **AC-1.** The workflow has `permissions: {}` at the top level and exactly the jobs `verify` then `publish`, both `runs-on: ubuntu-latest`, with no checkout `ref:` override, no stored token (`NODE_AUTH_TOKEN`, `secrets.`) and no `npm audit`.
- **AC-2.** `verify` holds exactly `contents: read`, no `id-token` and no `environment`. It runs `npm ci` and `npx vitest run`, carries both guard steps by name and their checks (`release.tag_name`, the `npm view "@yeison.restrepo.r/code-conductor@…"` lookup), and never runs `npm publish`.
- **AC-3.** `publish` has `needs: verify`, `environment: npm-publish` and exactly `id-token: write` and `contents: read`. It uses only `actions/checkout` (with `persist-credentials: false`) and `actions/setup-node` (with `registry-url: 'https://registry.npmjs.org'` and no cache). Its `run:` lines are exactly `npm install -g npm@^11.5.1 --ignore-scripts` and `npm publish --provenance --access public --ignore-scripts`. It contains no `npm ci`, `npm test`, `npm run`, `npx`, `vitest` or other `npm install`.
- **AC-4.** `vitest` and `@vitest/coverage-v8` share one range in `package.json`. The lockfile locks `vitest`, `@vitest/coverage-v8` and `@vitest/mocker` to one version at or above 4.1.12 and below 5.0.0. The range check is pinned at its edges: 4.1.11 and 5.0.0 are out, 4.1.12 and 4.99.99 are in, and a prerelease or missing version is out.
- **AC-5.** `package.json` has no runtime `dependencies` and none of the scripts `prepare`, `prepack`, `postpack`, `prepublish`, `prepublishOnly`, `publish` or `postpublish`.
- **AC-6.** `npm audit --package-lock-only` reports "found 0 vulnerabilities" at the PR head.
- **AC-7.** `npm test` stays green on all three test.yml legs. Each leg's "Assert the skipped set against the measured baseline" step passes with `tools/skip-baseline.json` unchanged, and `npm run coverage` meets the thresholds in `vitest.config.js` unchanged.

## Out of scope

Pinning Actions by commit SHA (BUG-070), extending `CONTROL_PLANE` (BUG-081), nested `CLAUDE.md` (BUG-082), the `npm-publish` environment's protection rules (repository settings), and the release records.
