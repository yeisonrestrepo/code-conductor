## [1.59.7] - 2026-11-26

### Fixed
- **[BUG-092]** The orchestrator's test-surface split between `test-writer` (test surface only) and `code` (outside it) can no longer be bypassed through the run's recorded test command. Guard 5 only gates the write tools, so a file changed while a role ran that command used to pass unseen. On a run with a test surface, `orchestrate.mjs install` now records in the run file, for each `test-writer` and `code` dispatch, a `build_tree` fingerprint: the sha256 of every tracked file that differs from `HEAD` and every untracked, non-ignored file, router files excluded (`treeFingerprint` and `buildTree` in `scripts/orchestrate.mjs`). At `handback`, the new `splitCheck` takes the fingerprint again and halts `ORCH_HANDBACK_SURFACE_CROSSED`, naming the files, when a file on the other role's side of the split changed during the dispatch, whatever `ops.f` lists. A missing or malformed fingerprint, or a git that can no longer list the tree, halts `ORCH_HANDBACK_SPLIT_UNVERIFIED`, and `resume` drops the fingerprint and re-dispatches the role with a fresh one; it does not revert the crossed files. The only fail-open case is a git already unavailable at `install`, recorded as `split check: unavailable (<reason>)` in the hand-back line. Both agent profiles and their `project-template/` copies, the four `cc-orchestrate` copies, the README, the wiki's band-roles page and the `[FEAT-033]` spec now state that Guard 5's split holds against direct writes only and describe the two halts. ## [1.59.5] - 2026-11-26

### Fixed
- **[BUG-095]** The `release: DISCARD` commands that `release.mjs check` prints after a rejected judgment no longer split a path in cmd.exe or PowerShell. A path with a space used to be single-quoted, which cmd.exe keeps as part of the argument, so `'a b'` reached git as `'a` and `b'`; a path with a comma such as `a,b.txt` was printed bare, which PowerShell reads as an array; and a path segment starting with `@` was printed bare, which PowerShell reads as splatting. No quoting means the same thing in a POSIX shell, PowerShell and cmd.exe, so a printed command now carries only paths that need none: the new `bareOnCommand` in `scripts/release.mjs` accepts a path only when it matches `BARE_PATH` (`[A-Za-z0-9._/:=@+-]`), does not start with `-` (Windows PowerShell splits `-x.txt`) and has no segment starting with `@`. Every other path, a space, comma, `$`, quote, cmd.exe metacharacter, control or non-ASCII character included, is printed on its own `release: DISCARD_BY_HAND` line as an escaped JSON string, and the `RELEASE_DISCARD_FIRST` warning names such a path by that same JSON string. A path with `@` inside a segment, such as `a@b.txt`, stays on its command. `shellQuote` and the handoff steps are unchanged. Pinned by the `(BUG-095)` `[AC8]` cases of `release.mjs check discards a rejected diff [BUG-090]` in `tests/scripts/release.test.js` (a comma, a leading `@`, a segment starting with `@`, a leading `-` and a `$` each on one `DISCARD_BY_HAND` line, `a@b.txt` staying bare, no printed command holding a quote or a non-bare path, and a control-plane `a,b/package.json` named by its JSON string in the warning); the `[AC7]` case now pins `--literal-pathspecs` with an untracked `:/x` while a tracked root `x` survives, and its renamed identity is updated in `tools/skip-baseline.json`. Landed from PR #331 (cc-lane-bot), intake of issue #321.

## [1.56.0] - 2026-11-23

### Added
- **[FEAT-035]** An eighth band role, `release`, seated in the Ship band, prepares one release through the new `/cc-release`, driven by the new `scripts/release.mjs` (no dependencies). The driver hardcodes no project fact: how a project releases is read from a committed profile, `.claude/release-profile.json` (version locations, changelog, tag format, remote, mainline, checks, publish step, backlog shapes, ticket writeback). `/cc-release --init` detects those values from the project's files and existing tags, shows them, and writes the profile only after the owner confirms (`RELEASE_PROFILE_EXISTS`, `RELEASE_PROFILE_IGNORED`, `RELEASE_INIT_VERSIONS_DISAGREE`). `/cc-release <version> [--items <IDs>]` runs `digest`, which refuses a dirty tree (`RELEASE_TREE_DIRTY`), a version that does not advance (`RELEASE_VERSION_NOT_ADVANCED`) or is not `MAJOR.MINOR.PATCH` (`RELEASE_VERSION_INVALID`), and an unknown or closed item (`RELEASE_ITEM_UNKNOWN`, `RELEASE_ITEM_NOT_OPEN`), and runs the profile's checks; it then dispatches the `release` agent inside an envelope whose `ops.scope` is the profile's surface, and `check` judges the uncommitted diff line by line against `HEAD` (`RELEASE_OUT_OF_SCOPE`, `RELEASE_CHANGELOG_SHAPE`, `RELEASE_BACKLOG_SHAPE`, `RELEASE_CLAIMS_MISMATCH`) and runs the checks again. The first red check halts as `RELEASE_HALT <name>: exit <rc>`. The profile is never on the release surface, and `check` fails with `RELEASE_PROFILE_CHANGED` if it differs from `HEAD`. A profile may set `changelog` to `null`, and the surface is then the version locations plus the bound backlog, with release notes from commit subjects. `/cc-release --handoff <version> [--pr <N>]` refuses unless the tree is clean, `HEAD` is the merged `main` and the tag does not exist (`RELEASE_NOT_RELEASED`, `RELEASE_NOT_ON_MAIN`, `RELEASE_TAG_EXISTS`), re-runs the checks, writes `.conductor/release/<version>/notes.md`, and prints the tag, push, publish and `[FEAT-031]` ticket-writeback steps, which the command runs only one explicit confirmation at a time and never with `--close`. On Windows, checks resolve through `PATH`/`PATHEXT`, and a `.cmd` or `.bat` program runs through `cmd.exe /d /s /c` with a driver-built, cross-spawn-style escaped command line; no profile text is ever a command line. The `release` profile holds `Read, Grep, Glob, Edit`, no shell, and exists only in SNAP `v: 6` envelopes (`MAX_VERSION = 6`); `snap-build` picks the lowest version whose roster names the role, so every v1-v5 envelope stays byte-identical. `orchestrate.mjs envelope release` installs the envelope scoped to the profile surface and refuses inside a live run; `release` stays out of `MODEL_ROLES`, and `scripts/release.mjs` and `.claude/release-profile.json` join the control-plane list. Guard 5's role roster and version check accept `release` at v6 and deny it the profile, and Guard 7 denies it any shell, identically in both hook copies.
